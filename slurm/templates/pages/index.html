  • Hardware Presets define reusable sets of physical node properties (boards, sockets, cores, memory, etc.). Assign a preset to a Node or Partition in their respective tabs — the properties are then written into slurm-nodes.conf and slurm-partitions.conf as the Defaults block template. Changes here do not take effect until you Save.
    How GRES works: Assign presets to Nodes to generate NodeName= lines in gres.conf and auto-populate Gres= in slurm-nodes.conf. Assigning a preset to a Partition is informational only — it annotates which GRES resources that partition exposes, but does not write any config lines by itself.
    Nodes represent individual compute nodes in the cluster. Assign a HWPreset to apply a set of hardware properties, and one or more GRES Presets to enable generic resources (GPUs, FPGAs, etc.) on that node. Gres= in slurm-nodes.conf and the corresponding NodeName= lines in gres.conf are generated automatically on Save. Add/Delete/Import requires the OOD manager toggle to be enabled.
    Partitions group nodes into logical job queues written to slurm-partitions.conf. Assign a HWPreset to set partition-level hardware defaults, and one or more GRES Presets to annotate which generic resources are available in this partition — GRES presets on a partition propagate to all nodes listed under it, automatically generating the corresponding NodeName= lines in gres.conf. Add/Delete requires the OOD manager toggle to be enabled.
